# Three-call parent RI-J repeatability diagnostic

This new campaign characterizes repeatability and sign reversal within one process. It preserves the failed signed diagnostic, original thresholds, qualified sources and all prior runs. Root must accept this protocol before preparation; a separate independent root review bound to preparation is required before launch. Implementation and synthetic tests may precede preparation. No native launch is authorized to the implementation agent.

## Fixed workload and controls

One fresh child, 1,000-second wall limit, sampled 10 GiB RSS guard, OMP4/OMP_DYNAMIC=FALSE, BLAS1, zero SCFs, zero PCM builds and no initial guess or effective-potential calls. The existing immutable MemoryRI implementation and process-group supervisor are reused. An unbuilt MemoryPCM attachment is permitted; unchanged MemoryRI setup calls its existing core-Hamiltonian helper. No allocator setting, source/runtime patch, oracle integrals or indefinite synthetic-density request is introduced.

Expected method: hypothetical P0_A parent with 196 atoms, 3,068 scalar spherical AOs, 1,568 explicit electrons, charge -8/spin 0, def2-SVP orbital basis and Mo def2-SVP ECP; PBE, grid level 2, direct SCF enabled with cutoff 1e-13, def2-universal-JKFIT auxiliary basis with 19,612 AOs. Unbuilt C-PCM settings remain eps=78.4, Lebedev order17, vdw_scale=1.2, r_probe=0 and frozen=false. Three output matrix payloads total 225,902,976 bytes, plus three NPY headers and small logs/JSON. This is an expected retained disk footprint, not an observed prelaunch result or a disk-enforcement bound.

Use one initially fresh RI-J object and one Cholesky factor for exactly three planned native get_j calls: +P0, +P0, -P0. P0 is the original saved cycle-zero parent density. Each call loads a fresh independent P0 buffer, verifies its byte digest agrees with the first positive buffer, negates it in place only for call 3, and verifies that the requested density bytes remain unchanged after return. Release the full density and returned J after each call, before the next native call. No regenerated density or SCF state is allowed.

On every native return, save the returned J to exclusive J1.npy, J2.npy or J3.npy, close it and hash the saved file **before** checking numerical acceptance, native call counts or storage invariants. A failure to return cannot provide a matrix; a save failure terminates without overwriting its partial artifact. Keep every saved file on every outcome. No result replaces old signed-run evidence.

Finite values, float64 shape (3068,3068), exact call counters, unchanged requested density, unchanged molecule/method/runtime, absent ERI/three-index cache and unbuilt PCM are continuation invariants. Require exactly one 19612-square immutable Fortran Cholesky factor, the same identity/pointer, and the same bounded-chunk content hash captured at creation and after each call. Hashing does not copy the factor and does not prove general native memory safety. Invariant failure aborts further calls. Numerical comparison or symmetry nonpass at the fixed threshold is recorded and does not by itself prevent the remaining planned diagnostic calls.

## Comparisons and retained observations

Read saved outputs and the original positive first-J file with read-only mmaps; compare at most 16 rows at once. For each difference record maximum absolute error, first row-major argmax, actual/reference/expected values at that location, operand maximum magnitudes, and count of entries exceeding **1e-10 absolute, rtol=0**. Do not fit or adjust tolerance.

The six comparisons are J2-J1 (same-sign repeat), J3+J1 and J3+J2 (sign reversal), and J1-Jold, J2-Jold and J3+Jold (external-run comparisons). Jold is the previously saved output of the same implementation, not an independent algorithmic oracle. Classify same-sign, sign-reversal and external-run comparisons separately; a nonpass identifies a consistency limitation without identifying its cause. The fixed sequence confounds sign with call order: a third-call difference cannot by itself be assigned specifically to sign. Save finite/symmetry summaries separately. Complete every comparison whose required matrices have been safely produced. Read-only --recompute reports the same metrics directly from the saved arrays and old reference without creating outputs or executing chemical operators.

After each saved return and its checks/comparisons, write and close one exclusive small buffered post-call-N.bin checkpoint, recording start and closed stages. Preserve existing native factor scans/logging and record runtime inventory, factor alias/content hashes, three native metric-call records, input hashes, output hashes, timings, stages, stdout/stderr and the full supervisor receipt. A missing, malformed or resource-terminated child outcome remains incomplete/failed and retains all records. Artifact hashing retains each successful hash independently and enumerates missing or unreadable files; one missing artifact never erases hashes of existing outputs.

## Gates and interpretation

Preparation verifies the qualified interpreter/runtime, saved parent input and accepted original first J, immutable helper/source pinsets, the failed signed diagnostic and its artifacts, and this campaign's driver/tests/protocol. Prepare creates no molecule and evaluates no operators. No silent retry, second child or reused run directory is allowed. Worker and launcher recheck a hash-bound launch gate.

Independent review file independent-root-review.json must contain status APPROVED_ONE_PARENT_J_REPEATABILITY_DIAGNOSTIC, independent_root_review=true, a nonempty reviewer, exact preparation_sha256 and qualification_artifacts equal to preparation.pins.qualification. Review digest is part of the launch gate. Only root may run --launch after review. CLI also exposes --prepare and --gate-check; --worker is internal and requires the saved launch gate and an exclusive claim.

A completed diagnostic with numerical nonpass is labeled COMPLETED_WITH_NUMERICAL_NONPASS; it is not numerical validation. All six comparisons and symmetry must pass before PASS_BOUNDED_PARENT_J_REPEATABILITY_ONLY is available, and accepted supervisor, three calls/metric records, one factor and all invariants are required for either completed status. Partial execution is INCOMPLETE_OR_FAILED_PARENT_J_REPEATABILITY. Neither completion state establishes exact replay of the missing failed SCF density difference, parent SCF readiness, allocator-trap cause, chemical validity or physical admission. Native requested allocation may exceed sampled resident memory; the guard is not a hard OS allocation cap.

Synthetic tests use tiny arrays and mocks for sign versus repeat failures, diagnostic continuation, saved output before invariant failure, exact calls, density/factor mutation, chunk maxima/counts, fresh claims, approval binding and child-failure preservation. They do not execute chemical operators.
