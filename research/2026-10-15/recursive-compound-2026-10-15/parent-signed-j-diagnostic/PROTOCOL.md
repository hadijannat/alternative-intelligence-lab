# Bounded signed parent RI-J diagnostic

Preparation only until an independent root review approves the exact preparation hash. This is a fresh diagnostic campaign; all earlier failures and immutable implementations remain unchanged. Success would constrain signed-density RI-J behavior, not establish parent SCF readiness, chemical validity, or the origin of the earlier allocator trap. The exact failing SCF density difference is unavailable to this campaign.

## Admission and fixed workload

Reuse the parent-openmp-first-j-v2 qualification, saved-cycle-zero density and parent-geometry helpers, the qualified runtime, unchanged MemoryRI implementation and unchanged process-group supervisor. Pin their sources, all first-J-v2 output files including the saved J, the failed saved-J pilot's executable/protocol/preparation/review and run-v1 files, and the final crash/allocation diagnostic sources and artifacts. Pin this run.py, test_run.py and protocol. Existing evidence is verified directly before preparation. Preparation builds no molecule and evaluates no chemical operators.

Only explicit --prepare, --gate-check and --launch commands are exposed; internal --worker requires a matching launch gate and an exclusive worker claim. Preparation is written once. independent-root-review.json must have status APPROVED_ONE_SIGNED_PARENT_J_DIAGNOSTIC, independent_root_review=true, a nonempty reviewer, exact preparation_sha256, and qualification_artifacts equal to preparation.pins.qualification. Root alone may launch after independent review. One fresh run-v1 directory, one child, no retries, no deleted failures. Gate and frozen-input hashes are rechecked before work and after the child.

One child gets 600 seconds and a sampled 10 GiB RSS guard, OMP4 with OMP_DYNAMIC=FALSE and BLAS1. This is not an OS allocation cap. Native source accounting suggests about 12.8 GB of requested data/workspace allocation across four threads before bookkeeping, which is not observed RSS. There is no four-GiB allocation bound. No allocator environment or installed runtime is changed.

Reconstruct the same hypothetical P0_A parent, scalar spherical def2-SVP basis with Mo ECP, charge -8/spin0, 3,068 AOs and 19,612 JKFIT auxiliary AOs. Use the unchanged MemoryRI setup and an unbuilt MemoryPCM. SCF, initial guess, density generation, effective-potential and PCM build entry points are forbidden. Normal unchanged MemoryRI installation invokes its existing core-Hamiltonian setup; no PCM/grid/surface build occurs.

Exactly two native get_j calls on the same initially fresh object are permitted. First use -P0, obtained by in-place negation of an independently loaded saved cycle-zero density. Check finite symmetric J and J(-P0)=-saved_J0 with absolute tolerance 1e-10 and rtol=0, using at most 16 matrix rows per comparison block and a read-only mmap of saved_J0. Record maxima and failures without relaxing thresholds. Release the full first density, returned J, and mmap before creating the second density.

Second use a fixed float64 symmetric density with D01=D10=0.01/sqrt(2) and all other entries zero. Validate AO0 and AO1 belong to atom0 Mo and record labels, shell indices and within-shell indices. Its two nonzero eigenvalues are analytically +/-0.01/sqrt(2); all remaining eigenvalues are zero. Its Frobenius norm is 0.01. No eigensolver is used.

Check second J finite and symmetric to 1e-10. Independently check all ten lower-triangle pairs from fixed selected AOs [0,1,1534,3067] at absolute tolerance 1e-10, rtol=0. For each pair, evaluate only its two orbital shells against the auxiliary basis through df.incore.aux_e2(mol,auxmol,shls_slice=(sa,sa+1,sb,sb+1,0,auxmol.nbas),intor=mol._add_suffix('int3c2e'),aosym='s1'). Extract the local AO vector. Construct b_L=2*D01*(01|L), solve once with the existing checked Cholesky metric, and take pair-vector dot products. This bypasses the native direct-JK contraction but shares its auxiliary metric and integral library. It is a selected-entry consistency oracle, not a full independent parent J oracle. Bound and record every returned shell buffer by 8*dsa*dsb*naux, using actual shell dimensions; the primary basis includes an f shell of dimension7, so no blanket primary-shell<=5 claim is allowed. No full three-index tensor is requested or retained.

## Storage and evidence

Require exactly one shared, read-only Fortran-order 19612-square Cholesky factor, unchanged object identity and data pointer after both calls and after the oracle. Keep no ERI or three-index cache/output. Record exactly two native metric-call callback records, plus one separately counted oracle metric solve. Factorization alias/pointer records, runtime observations, density summaries, selected AO metadata, bounds, native timings, stage JSONL, native/stdout/stderr logs and supervisor receipts remain available on failure.

Immediately after each returned call and its checks, write and close one fixed small buffered file named post-call-1.bin or post-call-2.bin using exclusive creation. Record a start stage before opening and a closed stage after the context exits. This deliberately adds a reproducible bounded allocation/close point after each native return; it does not diagnose allocator ownership by itself. Check failures are saved, then the child terminates; no second call follows a failed first check.

Success requires accepted supervisor receipt, exact check-name set with all checks true, two native J calls, two native metric records, one factor, one oracle solve, zero SCFs, fixed artifacts and unchanged gate. Any signal, timeout, RSS termination, missing result, malformed result, changed pin or failed numerical check produces an incomplete/failed launcher result retaining all existing files. Neither outcome authorizes a larger run or retry.

Synthetic tests use tiny arrays and fake molecules/operators to exercise chunk/sign failures, shell-index extraction, ten selected pairs, forbidden entry points, exact call counts, fresh claims, approval/hash binding and supervisor failure preservation. Preparation and tests launch no chemical operators.
